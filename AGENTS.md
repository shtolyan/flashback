# Flashback

Основное приложение — `~/flashback`. Production работает в Сингапуре: https://flashback.62-146-235-120.sslip.io. Один экземпляр содержит собственную PostgreSQL-базу и API. HexLive переключён 2026-09-10; прежний production `/api/bugs/v1` проксирует в Flashback. Старую SQLite не использовать как актуальный источник. Локальная база — копия для разработки.

- Архитектура и запуск: README.md. Совместимый API и рабочий процесс агентов: docs/API.md.
- Сохраняйте `/api/bugs/v1`, имена полей, статусы, прежний массив GET /reports и проверку expectedRevision.
- Клиент: Expo SDK 57. Перед изменением Expo API сверяйтесь с https://docs.expo.dev/versions/v57.0.0/.
- Все записи выполняются через сервис и транзакции PostgreSQL; события отправляются только после commit.
- Миграции добавляются по порядку; уже применённые миграции не переписывать.
- UI не должен терять поиск, страницу, позицию списка и черновик при фоновых обновлениях.
- Проверки: npm run typecheck, npm test, браузерные сценарии для изменений интерфейса. Обычные тесты не должны менять production. Проверки деплоя могут создавать и удалять только собственные временные записи.
- Не включайте .env, выгрузки, резервные копии и данные в Git.
- Все запросы, включая чтение и создание, требуют Bearer-ключа. Используйте свой ключ с ограниченными статусами; секреты не выводите. Администратор управляет ключами в UI.
- Агенты не подтверждают fixed и не архивируют баги за игрока.
