# Ключи агентов по устройствам — 2026-09-12

Агенты используют отдельные ключи устройства. Имена ключей обозначают устройство,
а не конкретного человека или модель агента. Сервер сохраняет фактически
авторизовавший запрос ключ; старую атрибуцию отчётов не переписываем.

| Устройство | Имя ключа | ID |
| --- | --- | --- |
| Mac | MacBook Air | `20ab7e78-e53a-4d84-aa8b-95b322151092` |
| Windows MSI | MSI ноутбук | `41ccb26e-136b-4639-9dda-54a84ac144d4` |

Оба ключа допускают `created`, `in_progress`, `ready_for_test`, `rework`.
Управление ключами и статус `fixed` им недоступны.

Клиент HexLive и оба build-скрипта читают только локальный файл:
- macOS: `~/.config/hexlive/bug-token`;
- Windows: `%USERPROFILE%\.config\hexlive\bug-token`.

Явный `--token-file` выбирает только указанный файл. Если файл отсутствует или
некорректен, операция завершается ошибкой. Переменная `HEXLIVE_BUG_TOKEN` и
репозиторный файл больше не подменяют ключ; build-скрипты устанавливают свою
процессную переменную из локального файла устройства.

Перед работой: `python .agents/skills/hexlive-bug-tracker/scripts/bugs.py whoami`.
Команда выводит имя, ID, права и путь файла, никогда не секрет.

В общих инструкциях обоих ноутбуков убран выбор персонального ключа «Светочка».
Старое локальное имя файла `sveta-bug-token` временно оставлено как hard link
на ключ текущего устройства для уже работающих агентов. В новых инструкциях
и командах оно не используется. Старые репозиторные файлы убраны на обоих
ноутбуках, включая найденную старую рабочую копию на Mac.

Прежние ключи «Светочка ✨» (`13e2cb42-badd-4968-8f3f-9d986b5622f6`) и
«HexLive agents» (`1342fb65-8c79-45a2-bd0a-e5e3e5bfd887`) отозваны.
Проверено: старые секреты получают HTTP 401; оба устройства проходят
авторизацию своими ключами. Ключи игрока и администратора не изменялись.
