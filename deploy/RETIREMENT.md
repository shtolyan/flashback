Единый рабочий адрес: https://flashback.62-146-235-120.sslip.io.
Каждый запрос API требует ключа Flashback. Старые SQLite больше не работают.

## Удаление кода и серверных маршрутов

В `simple-diple/HexLive`, ветка `master`, опубликован коммит
`1f4f1c3a0f781e9a7990a747576f2347fed6d006`. Он удаляет пять файлов встроенного
трекера, Microsoft.Data.Sqlite, создание/импорт базы и старые HTML-формы.
В игровом сервере остаётся только `RetiredBugTracker`: любой метод на
`/api/bugs/v1` и `/admin/bugs`, включая вложенные пути, получает 410.
Админка игры ссылается на Flashback. Игровой HTTP-клиент, CLI и build scripts
используют прямой Flashback URL и Bearer. Аргумент `-hexlive-bugs-api` сохранён.
`hexlive-integration.patch` содержит тот же изолированный коммит.

Развёртывание выполнено отдельно от посторонних локальных изменений HexLive:

- Singapore: `/opt/hexlive/releases/6bb99f9d7f9d28a083f8010fc34aea9b827ac7e9-flashback-retired`.
- New York: `/opt/hexlive/releases/be67c908f282b4fbccd99d7d8e9101e4acf9fca6-flashback-retired`.

Каждая сборка использует исходную версию симуляции своего сервера с удалением
трекера. При штатном SIGINT-перезапуске сохранены существующие world.sav,
админка, игровые ключи, настройки, seed, topology и tick. Сингапурский staging
5124 предшествует реализации трекера: код и SQLite отсутствуют, API возвращает 404.

`vmi3529459.contaboserver.net` и прямой Singapore :5123 возвращают 410 для
старого трекера. New York HTTPS `/api/bugs/v1` остаётся совместимым прокси
к Flashback; прямой :5123 возвращает 410. На старом сингапурском адресе
проксирование опасно из-за пересечения ID разных отчётов, поэтому его нет.
Игра, Asset API и остальные маршруты продолжают работать.

## Копии и повторный запуск

На обоих игровых хостах `/var/backups/flashback-retirement-20260910/` содержит
финальную SQLite, архив старых tracker-файлов, состояние мира перед заменой,
прежний release path и проверки игрового состояния до/после.
Каталог доступен только root; секреты не публикуются в Git.
Вместо runtime-файла `hexlive-bugs.sqlite3` оставлен пустой каталог mode 000:
случайный запуск старой сборки не сможет создать там новый SQLite tracker.
**Не удалять этот барьер и не возвращать старые writer-сборки.**

На Singapore `/opt/flashback/backups/legacy-retirement-20260910/` содержит
`before-reconcile.dump`, `after-reconcile.dump`, исходные снимки и результаты
объединения. После остановки серверов NYC-снимок не изменился; SG-финальный
снимок содержит последнюю дополнительную правку #396.

`export-legacy-sqlite.py` читает архив без запуска старого сервера.
`merge-retired-hexlive.ts` по умолчанию проверяет объединение и откатывает
транзакцию; `--apply` фиксирует под блокировкой таблиц с проверкой каждого поля.
Данные Flashback, изменённые после исходного снимка NYC, имеют приоритет.

Применены ровно два прохода, оба записаны в `import_history`:

1. `sg.json` против `nyc.json`: fingerprint
   `retired-sg-v1:6914e70b12877f0487456aea06e29e7d51be9d0ce9b1d94242722b6d284b8100`.
2. `sg-final-delta.json` (только #396) против `sg.json`: fingerprint
   `retired-sg-v1:9c2ea6dcc09618fe894e66e7240125004cdbf3b830ce99fa88a63b109e01a3d0`.

Повтор тех же входов не меняет данные. Не запускать полный `sg-final.json`
как новую миграцию поверх выполненной: переименованные ID уже существуют;
любое дальнейшее восстановление должно учитывать сохранённую таблицу номеров.
Для отката приложения сохранять текущий PostgreSQL. Старые SQLite — архивы,
а не допустимый способ отката после продолжения работы в Flashback.
