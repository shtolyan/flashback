# Flashback

Простой баг-трекер: React Native + Expo 57 для веба, PWA, iOS и Android; собственный сервер Fastify + PostgreSQL 18. Один экземпляр — один проект. API совместим с HexLive. Вход и пользовательские аккаунты не требуются.

## Production

**https://flashback.62-146-235-120.sslip.io** — рабочий трекер HexLive в Сингапуре. HTTPS обслуживает Caddy, поэтому порт вводить не нужно. Старый production API HexLive прозрачно проксирует в эту же PostgreSQL-базу. Инструкции сервера: [deploy/README.md](deploy/README.md); результат переключения: [deploy/CUTOVER.md](deploy/CUTOVER.md).

## Запуск

Локальная копия для разработки на этом Mac запущена через Compose: **http://localhost:4310**. Повторный запуск: `docker compose --profile app up -d`. Перед переходом в режим разработки остановите только контейнер приложения: `docker compose stop app`, чтобы освободить порт 4310.

Нужны Node.js 24+ и Docker с Compose. На этом Mac используется уже работающий Docker-контекст `colima-backtracker`; Flashback имеет отдельный контейнер PostgreSQL и том `flashback_pgdata`.

```sh
cd ~/flashback
npm ci
cp .env.example .env  # только при первой настройке; не перезаписывайте существующую .env
npm run dev
```

`dev` поднимает PostgreSQL, сервер на порту 4310 и Expo Web на 8082. Для работы с собранной версией:

```sh
npm run db:up
npm run build:web
npm start
```

Открыть **http://localhost:4310**. Веб и API обслуживает один процесс. Миграции применяются автоматически перед запуском API. База хранится в Docker volume и переживает перезапуск.

Остановить PostgreSQL: `npm run db:stop`. Не удаляйте том, если нужны данные.

## Собственный экземпляр

Настройки находятся в `.env`: `DATABASE_URL`, `PORT`, `HOST`, `INSTANCE_NAME`, `REPOSITORY_URL`. Копия проекта с другим Compose project name (`COMPOSE_PROJECT_NAME`), портами и отдельным томом является независимым экземпляром. У него нет зависимости от рабочего HexLive.

Полный контейнерный запуск: `docker compose --profile app up --build -d`. Экземпляр без настроенной авторизации доступен всем, кто может подключиться к его порту — это выбранный режим первой версии.

## Данные HexLive

```sh
npm run import:hexlive
# Или импорт ранее сохранённого снимка:
npm run import:hexlive -- data/hexlive-<fingerprint>.json
```

Источник по умолчанию — рабочий `/api/bugs/v1` HexLive; переопределение: `HEXLIVE_SOURCE_API`. Скрипт только читает источник, сохраняет снимок в `data/` и переносит отчёты, комментарии, ревизии, версии и все доступные патчи в собственную базу. Он сохраняет исходные ID и сверяет каждое поле после переноса. Патч, который не загружен на источник, не выдумывается.

Повтор того же снимка ничего не перезаписывает. Импорт другого снимка в непустую базу отклоняется, чтобы не потерять локальные правки. Это разовая копия, не двусторонняя синхронизация. После переключения 2026-09-10 актуальные данные находятся в production Flashback. Старый API теперь возвращает ту же новую базу; исторический снимок SQLite сохранён в резервных копиях. Для обычной работы используйте production URL, а локальную базу — только для разработки.

## Агенты и API

Описание: [docs/API.md](docs/API.md), машиночитаемая схема: http://localhost:4310/openapi.json.

```sh
python3 scripts/bugs.py queue
python3 scripts/bugs.py get 375
# Подключиться к другому экземпляру:
FLASHBACK_API=https://tracker.example.com/api/bugs/v1 python3 scripts/bugs.py list
```

Неизменённый клиент HexLive работает с `--api http://localhost:4310/api/bugs/v1` и своим прежним токеном. Игра принимает `-hexlive-bugs-api <base-url>`. Заголовки Bearer совместимы, но новый экземпляр их не требует и не использует для авторизации.

## Телефон и нативные приложения

Во время разработки телефон и Mac должны видеть друг друга по сети. Запустите `npm run dev` и откройте Expo Go через QR-код. API-адрес выводится из адреса Expo-сервера, порт 4310. Веб-версия доступна по `http://<IP-Mac>:4310`.

```sh
npm run android
npm run ios
```

Для эмулятора Android с Expo `--localhost` дополнительно: `adb reverse tcp:4310 tcp:4310`.

Установленное приложение должно знать адрес экземпляра: задайте `EXPO_PUBLIC_API_URL=https://tracker.example.com` при сборке. В `apps/client/eas.json` есть профили development / preview / production. Создание подписанных IPA/AAB, учётные записи магазинов и публикация — отдельный этап. Для локального нативного запуска также доступны `npx expo run:android` и `npx expo run:ios` из `apps/client`.

PWA устанавливается через браузер на HTTPS или localhost. При первом подключении сохраняется оболочка приложения, включая JavaScript. Данные API не сохраняются сервис-воркером, а записи без сети не ставятся в очередь: черновик остаётся в текущем сеансе, ошибка отображается явно.

## Резервные копии

```sh
npm run backup
npm run restore -- backups/flashback-<date>.dump flashback_restored
```

`pg_dump` создаёт согласованный снимок работающей базы. Восстановление выполняется через `pg_restore` одной транзакцией в **новую именованную базу**, существующая не перезаписывается. Чтобы использовать восстановленную базу, укажите её имя в `DATABASE_URL` и перезапустите сервер. Команды рассчитаны на PostgreSQL из этого Compose; для внешнего PostgreSQL используйте его `pg_dump`/`pg_restore`.

## Проверка и структура

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:ui  # сервер и веб-сборка должны работать на localhost:4310
```

API-тесты создают временную PostgreSQL-базу и удаляют её после проверки. Браузерные тесты создают и удаляют только свои тестовые отчёты на локальном экземпляре. Рабочий сервер HexLive не изменяется.

- `apps/client`: интерфейс, навигация, запросы, WebSocket и PWA.
- `apps/server`: HTTP-контракт, операции и транзакционный доступ к PostgreSQL.
- `packages/contracts`: общие типы и схемы запросов.
- `scripts`: миграции, перенос, резервные копии и клиент агента.
- `tests`: совместимость, конкурентность, интерфейс и восстановление соединения.

Схема изменяется версионированными миграциями. Сначала транзакция PostgreSQL фиксируется, затем сервер отправляет событие клиентам. Один процесс обслуживает экземпляр; перед горизонтальным масштабированием нужно подключить общий источник событий (например, PostgreSQL LISTEN/NOTIFY). Авторизация может быть добавлена в HTTP-слое без изменения модели отчёта.
